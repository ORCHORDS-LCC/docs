## Adoption review

1. Confirm the document is current. The index entry records the status and any successor, and the errata system records the corrections to a document that is immutable after publication.
2. Identify the category the document falls into, because the category decides how much of it is binding. The index entry for this RFC records the status as INFORMATIONAL.
3. Extract the normative requirements. Separate MUST-level obligations from SHOULD-level recommendations and from purely informative text.
4. Record the dependencies. A document that references another specification inherits that dependency for the parts that cite it.
5. Decide which obligations fall on the protocol author, the implementer, and the operator separately.
6. Record any parameter the document leaves to the implementer, and the value chosen.
7. Note the interoperability constraints: wire formats, state machines, and error handling that peers will assume.
8. Set the re-review trigger: a successor document, an errata update, or a deployment change.
