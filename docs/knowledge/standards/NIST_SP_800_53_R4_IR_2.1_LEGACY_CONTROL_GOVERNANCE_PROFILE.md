# Simulated Events Legacy Control Governance Profile

## Reference

- Control: **ir-2.1 — Simulated Events**
- Family: ir
- Catalog: NIST SP 800-53 Rev. 4

## Control statement



## Governance pattern

1. Confirm the control applies to the system, service, or process in scope, and record the applicability decision.
2. Resolve every organization-defined parameter before treating the control as satisfied.
3. Identify the responsible role for each part of the statement, including parts fulfilled by a supplier or a shared platform.
4. Read the associated discussion and any additional control guidance before designing the implementation.
5. Record the evidence that would demonstrate the control is operating, not only that a policy exists.
6. Review the statement when the catalog is revised, when the system changes materially, or when inherited responsibilities change.

## Controls and evidence

Evidence of a functioning control includes:

- the current statement and the resolved parameters, with the resolution recorded;
- design or architecture evidence showing how the requirement is met;
- configuration or policy evidence for the implemented part;
- operational records showing the control operating over time;
- supplier or inherited-control evidence where responsibility is shared;
- a documented exception with a compensating control and an expiry date.

## Limitations

A catalog statement describes what a control requires in general terms. It does not establish that any particular implementation satisfies it, and it does not replace the assessment evidence.
